# تمرین جلسه پنجم

# نام پروژه
**رزرو خودرو توسط کاربران**

---

# 1. تعریف محصول (Product Definition)

## 1-1. معرفی محصول

سامانه رزرو خودرو توسط کاربران یک سیستم تحت وب یا موبایل است که به کاربران امکان می‌دهد خودروهای موجود را مشاهده کرده، اطلاعات آن‌ها را بررسی کنند و در صورت نیاز، خودرو موردنظر خود را برای زمان مشخص رزرو نمایند. همچنین مدیر سیستم می‌تواند خودروها، کاربران و تمامی رزروها را مدیریت کند.

---

## 1-2. هدف محصول

اهداف این سامانه عبارت‌اند از:

- ساده‌سازی فرآیند رزرو خودرو
- کاهش مراجعات حضوری
- جلوگیری از رزرو همزمان یک خودرو توسط چند نفر
- مدیریت بهتر اطلاعات خودروها و کاربران
- افزایش سرعت و دقت در ارائه خدمات

---

## 1-3. کاربران سیستم

### کاربران عادی

| قابلیت |
|---|
| ثبت‌نام در سیستم |
| ورود به حساب کاربری |
| مشاهده خودروهای موجود |
| جستجوی خودرو |
| رزرو خودرو |
| لغو رزرو |
| مشاهده سوابق رزرو |

### مدیر سیستم

| قابلیت |
|---|
| مدیریت کاربران |
| مدیریت خودروها |
| مدیریت رزروها |
| مشاهده گزارش‌ها |
| اضافه، ویرایش و حذف خودرو |

---

## 1-4. قابلیت‌های اصلی محصول

| # | قابلیت |
|---|---|
| 1 | ثبت‌نام کاربران |
| 2 | ورود کاربران |
| 3 | نمایش لیست خودروها |
| 4 | نمایش مشخصات خودرو |
| 5 | جستجوی خودرو |
| 6 | رزرو خودرو |
| 7 | لغو رزرو |
| 8 | مدیریت خودروها |

# 2. مرحله اول SDLC (Planning)

## 2-1. تعریف مسئله

در بسیاری از مراکز اجاره خودرو، فرآیند رزرو به‌صورت تلفنی یا حضوری انجام می‌شود که باعث اتلاف زمان، افزایش احتمال خطا و نارضایتی مشتریان می‌شود. بنابراین طراحی یک سامانه آنلاین برای رزرو خودرو ضروری است.

---

## 2-2. اهداف پروژه

- ایجاد امکان رزرو اینترنتی خودرو
- کاهش زمان انجام فرآیند رزرو
- جلوگیری از تداخل رزروها
- مدیریت اطلاعات کاربران و خودروها
- افزایش رضایت کاربران

---

## 2-3. محدوده پروژه

این پروژه شامل موارد زیر است:

- ثبت‌نام کاربران
- ورود کاربران
- مشاهده خودروها
- جستجوی خودرو
- رزرو خودرو
- لغو رزرو
- مدیریت خودروها
- مدیریت کاربران
- گزارش‌گیری

موارد خارج از محدوده پروژه:

- پرداخت آنلاین
- ارسال خودرو
- تعمیر و نگهداری خودروها

---

## 2-4. امکان‌سنجی اولیه

### امکان‌سنجی فنی

با استفاده از فناوری‌های توسعه وب و پایگاه داده، پیاده‌سازی این سامانه امکان‌پذیر است.

### امکان‌سنجی اقتصادی

هزینه توسعه سامانه نسبت به کاهش هزینه‌های مدیریت و افزایش کیفیت خدمات مناسب است.

### امکان‌سنجی عملیاتی

کاربران به‌راحتی می‌توانند از سامانه استفاده کنند و مدیر نیز قادر به مدیریت اطلاعات خواهد بود.

---

# 3. مرحله دوم SDLC (Requirement Analysis)

## 3-1. نیازمندی‌های کارکردی (Functional Requirements)

| # | نیازمندی |
|---|---|
| 1 | کاربر بتواند ثبت‌نام کند. |
| 2 | کاربر بتواند وارد سیستم شود. |
| 3 | کاربر بتواند خودروهای موجود را مشاهده کند. |
| 4 | کاربر بتواند خودرو را جستجو کند. |
| 5 | کاربر بتواند خودرو را رزرو کند. |
| 6 | کاربر بتواند رزرو خود را لغو کند. |
| 7 | مدیر بتواند خودرو جدید اضافه کند. |
| 8 | مدیر بتواند اطلاعات خودرو را ویرایش کند. |
| 9 | مدیر بتواند خودرو را حذف کند. |
| 10 | مدیر بتواند کاربران و رزروها را مدیریت کند. |

---

## 3-2. نیازمندی‌های غیرکارکردی (Non-Functional Requirements)

- امنیت اطلاعات کاربران
- سرعت مناسب پاسخ‌گویی سیستم
- رابط کاربری ساده و قابل فهم
- قابلیت توسعه در آینده
- دسترس‌پذیری مناسب سامانه

---

## 3-3. محدودیت‌ها (Constraints)

- هر خودرو در یک بازه زمانی فقط برای یک نفر قابل رزرو است.
- استفاده از اینترنت برای دسترسی به سامانه الزامی است.
- فقط کاربران ثبت‌نام‌شده امکان رزرو خودرو را دارند.

---

## 3-4. فرضیات (Assumptions)

- کاربران اطلاعات صحیح وارد می‌کنند.
- خودروها توسط مدیر به‌روز نگهداری می‌شوند.
- سرور سامانه همیشه در دسترس است.

---

## 3-5. ذی‌نفعان (Stakeholders)

| ذی‌نفع | نقش |
|---|---|
| کاربران | استفاده‌کنندگان سامانه |
| مدیر سامانه | مدیریت و نظارت |
| شرکت ارائه‌دهنده خدمات خودرو | مالک کسب‌وکار |
| تیم توسعه نرم‌افزار | پیاده‌سازی و نگهداری |

---

# نتیجه‌گیری

با انجام مرحله تعریف محصول و دو مرحله نخست SDLC، نیازهای اصلی سامانه مشخص شده و پروژه برای ورود به مرحله طراحی آماده خواهد بود.
